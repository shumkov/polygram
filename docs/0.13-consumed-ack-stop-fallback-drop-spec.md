# 0.13 — consumed-ack swallows a substantive Stop-fallback reply (silent drop)

**Status:** spec / awaiting sign-off · **Severity:** partner-facing reliability ·
**Found:** 2026-06-13 production (Shumabit@UMI, thread 37, msg 2956)

## Symptom

A partner asked a research question; the agent acked "Researching now…", did ~6 min
of real work, and the **final answer never arrived**. The topic went silent for
**5h20m** until the partner re-initiated. The turn was recorded `result_subtype=success`
and the daemon logged `channels-delivered` — but **no outbound row was ever written and
the user received nothing.**

## Production trace

```
[Shumabit@UMI/37] channels: tool-call name=reply ... text_len=294      ← "Researching now…" ack (delivered ✓)
[Shumabit@UMI/37] cli: turn finalized via stop-hook fallback (no reply tool call); text_len=2066
[Shumabit@UMI/37] 374.5s | 2066 chars | channels-delivered | opus/high  ← logged from the alreadyDelivered short-circuit
```
Two near-simultaneous inbounds (01:45:10 + 01:45:24) folded. The agent sent ONE reply
(the 294-char ack) **and** named the sibling turn in `consumed_turn_ids`. It then produced
the real **2066-char** answer as plain assistant text (no `reply` tool call). The sibling
turn finalized via the **Stop-hook fallback**, pulling that 2066-char text from
`lastAssistantMessage`.

## Root cause

`lib/process/cli-process.js::_finalizeTurn` (line ~1915):

```js
alreadyDelivered: hadReplyToolCalls || pending._consumedAcked === true,
```

`_consumedAcked` (set in `_ledgerAckConsumed`, line ~1554) means "a sibling reply named
this turn in `consumed_turn_ids`." The finalize then assumes that sibling **delivered this
turn's answer**. That assumption holds for a genuine fold (claude answered both turns in
one reply). It is **false** when the sibling reply was only an *ack* and the real answer
arrived later as Stop-fallback text. `alreadyDelivered=true` makes `polygram.js` (lines
1395-1410) take the short-circuit branch — which **sends nothing** (it assumes incremental
reply-tool delivery already happened) yet logs `channels-delivered`. The substantive
answer is dropped silently.

## Fix

Record **what the consuming reply actually delivered**, and only treat a consumed-acked
turn as already-delivered when the Stop-fallback text matches that delivered text.

1. `_ledgerAckConsumed(ids, consumingText)` — store `pending._consumedByText = consumingText`
   next to `pending._consumedAcked = true` for each consumed pending.
2. Call site (line ~1162): pass `args.text` (the consuming reply's text).
3. `_finalizeTurn`: a turn that rescued text via the Stop fallback (`!hadReplyToolCalls &&
   text`) is only `alreadyDelivered` via the consumed-ack path when the fallback text
   equals (trimmed) what the consuming reply delivered:

```js
const usedStopFallback = !hadReplyToolCalls && !!text;
const norm = (s) => (s || '').trim();
const consumedCoversFallback = !usedStopFallback || norm(text) === norm(pending._consumedByText);
const alreadyDelivered = hadReplyToolCalls
  || (pending._consumedAcked === true && consumedCoversFallback);
```

4. When the consumed-ack did NOT cover the rescued text (the bug path), emit
   `cli-consumed-ack-fallback-rescued` for forensics so we can see the fix firing in prod.

## Why this is safe (double-delivery analysis)

The dangerous direction is a **false negative** (delivering text the user already saw). The
fix only flips `alreadyDelivered` true→false when **all** hold: no reply tool calls this
turn, the Stop fallback produced substantive text, `_consumedAcked` is set, AND that text
≠ the consuming reply's text. Cases:

- **Prod bug:** fallback (2066) ≠ ack (294) → deliver. ✓ (the fix)
- **Genuine fold:** consuming reply carries the combined answer; the consumed turn's
  fallback text equals it (or is empty) → suppressed, no duplicate. ✓
- **Fold + trailing plain-text summary** (fallback ≠ consuming reply, genuinely new text):
  old code dropped it; new code delivers it. This is **new** content, not a duplicate —
  acceptable, arguably correct. Noted as the one behavior change.
