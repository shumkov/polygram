# Polygram 0.8.0 — SDK Migration Plan

**Goal:** Replace the `child_process.spawn('claude', [...])` plumbing in
`lib/process-manager.js` with `@anthropic-ai/claude-agent-sdk`'s typed
control plane, **without** regressing any user-visible behaviour or
losing existing operational features.

This is an architectural refactor, not a feature change. Every existing
polygram capability MUST keep working; the migration unlocks
capabilities that are currently impossible (D mid-turn steer, E clean
interrupt, F live cost telemetry — already partially landed in 0.7.6
but we're stuck parsing stream-json instead of typed events) and
removes plumbing we shouldn't own (transcript persistence, approval-hook
IPC, OAuth shell-out for `claude /login`).

---

## Why migrate

| Feature | Today | After SDK | Win |
|---|---|---|---|
| **D — mid-turn steer** | Not possible (claude CLI is request-then-stream; new stdin writes get separate `result` events, FIFO) | `query.streamInput({ priority: 'now', shouldQuery: false })` injects into the live turn | True OpenClaw parity |
| **E — clean interrupt** | `proc.kill('SIGTERM')` — loses session context, requires respawn | `query.interrupt()` — graceful, retains session | No 30s respawn after stop |
| **F — typed cost telemetry** | Parse `total_cost_usd` from `result` event + sum `usage.*_tokens` from assistant events | Typed `ModelUsage` per message + `query.getContextUsage()` for live "context full" warnings | Less brittle, gains live context-window awareness |
| **canUseTool** | `bin/approval-hook.js` IPC over Unix socket → polygram daemon | In-process callback `canUseTool(name, input, opts)` | Drop ~300 LOC of IPC plumbing |
| **Auth** | User runs `claude /login` interactively, OAuth tokens in keychain | `SDKControlClaudeAuthenticate*` in-process | Daemon can refresh tokens without TTY |
| **Session storage** | Hand-rolled `sessions` table + `--resume <id>` | Pluggable `sessionStore` interface (Postgres/S3/Redis examples shipped) | Drop bespoke transcript layer when ready |
| **MCP servers** | Whatever's in `~/.claude.json`/`settings.json` | Typed `mcpServers: { name: McpServerConfig }`, `query.toggleMcpServer()` mid-session | Per-chat MCP overrides become trivial |
| **Mid-session config** | Restart process for `/model`, `/effort`, `/permission-mode` change | `query.setModel()`, `setMaxThinkingTokens()`, `setPermissionMode()` mid-session | No respawn for config tweaks |

**Loss inventory** (everything that gets *worse*):

- **pid-level SIGKILL.** SDK exposes `close()` (graceful) and
  `interrupt()` (cancel turn). For "fully kill stuck worker," the SDK
  still spawns claude underneath as a child of the SDK process — so we
  could drop to `child_process` if we kept a reference to the SDK's
  internal proc. We don't have to lose this entirely; it just becomes
  a SDK-internals dependency that may break across versions. Mitigation:
  document the workaround, prefer `interrupt()` in normal flow.
- **Per-bot `claude` binary version.** Today: `CLAUDE_BIN` env var pins
  a path per bot. SDK: pins one CLI version per Node module. Mitigation:
  one polygram daemon per bot already (separate launchd jobs), each can
  pin its own `@anthropic-ai/claude-agent-sdk` version via
  `package.json` if we ever needed divergence (we never have).
- **stdout/stderr scraping ergonomics.** Less of an issue with the
  typed event stream; logs become structured JSON we tee to disk.

**Things that DON'T change (key reassurances for "no regression"):**

- One Node daemon per bot still. shumabit and umi-assistant remain
  separate processes managed by separate launchd plists. A crash in
  shumabit cannot affect umi-assistant.
- Per-chat isolation still. Each chat gets its own `query()`
  invocation; the SDK spawns one claude worker per `query()`. A crash
  in one chat's worker only affects its session.
- All polygram features ship: streaming preview, chunked redelivery,
  voice transcription, sticker map, status reactions, approval flow,
  /pair-code, /approvals, IPC for cron, etc. The migration is purely
  about replacing `spawn(claude)` with `query()`.

## Architecture before vs after

### Before (today, 0.7.6)

```
shumabit launchd plist
  └─ polygram daemon (Node)
      ├─ ProcessManager (LRU pool of claude subprocesses)
      │   └─ 1 claude subprocess per active sessionKey
      │       ├─ stdin: JSON-encoded user messages
      │       ├─ stdout: stream-json events (init / assistant / result)
      │       └─ approval hook subprocess → IPC socket → polygram
      ├─ Telegram polling loop (grammy)
      ├─ IPC server (Unix socket) for cron + approval hook
      └─ SQLite (better-sqlite3) for transcripts, events, etc.
```

### After (target, 0.8.0)

```
shumabit launchd plist
  └─ polygram daemon (Node)
      ├─ ProcessManager (LRU pool of Query objects)
      │   └─ 1 Query (AsyncGenerator) per active sessionKey
      │       ├─ streamInput(): typed message stream IN (priority, shouldQuery)
      │       ├─ AsyncGenerator: typed event stream OUT (SDKMessage union)
      │       └─ canUseTool callback: in-process, no IPC
      ├─ Telegram polling loop (grammy)               [unchanged]
      ├─ IPC server (Unix socket) for cron only       [approval hook removed]
      └─ SQLite                                        [unchanged]
```

The shape stays the same: ProcessManager owns N "things" keyed by
sessionKey, each "thing" exposes a way to send and receive. We're
swapping the implementation of one "thing" from `child_process` +
stream-json parsing to SDK `Query` + typed events.

## Migration phases

### Phase 0 — Spike & validate (1 day)

Goal: prove the SDK can do everything we need on a throwaway branch.

1. Create `0.8.0-spike` branch.
2. Add `@anthropic-ai/claude-agent-sdk` to `package.json`.
3. Write a tiny standalone script `scripts/sdk-spike.js` that:
   - Calls `query({ prompt: 'hello', options: {...} })`.
   - Iterates the AsyncGenerator, prints typed events.
   - Exercises `streamInput({ priority: 'now' })` mid-turn.
   - Exercises `interrupt()` mid-turn and verifies session state.
   - Exercises `canUseTool` rejecting a Bash call.
   - Exercises resume via `resume: sessionId`.
   - Verifies `usage.cache_read_input_tokens` is reported.
4. Confirm cwd / HOME / env passthrough behaves the same as
   `child_process.spawn` (memsearch + skills must keep working).

**Exit criteria for Phase 0:** all six SDK features verified on
spike script. If any fails, document the gap and decide whether to
defer or work around. **Do not proceed to Phase 1 until this passes.**

### Phase 1 — Internal refactor of `lib/process-manager.js` (2 days)

Goal: keep the public ProcessManager API stable; swap the internals.

1. Rename old file → `lib/process-manager-cli.js` (kept for
   reference + rollback during Phase 5 soak).
2. Write new `lib/process-manager.js`:
   - Same constructor signature: `cap`, `queueCap`, `spawnFn`, `db`,
     `logger`, `onInit`, `onResult`, `onClose`, `onStreamChunk`,
     `onToolUse`, `onAssistantMessageStart`, `onRespawn`,
     `onQueueDrop`. The `spawnFn` injection point becomes the SDK
     options factory (`(sessionKey, ctx) → SdkOptions`).
   - Same public methods: `getOrSpawn`, `send`, `shutdown`,
     `_logEvent` (private), plus introspection getters.
   - Internally: each entry holds a `Query` instead of a `proc`.
     `entry.proc.stdin.write(JSON.stringify({type:'user',...}))` becomes
     `entry.query.streamInput({ message, priority: 'next' })`.
     The pendingQueue still exists — it's the user-message-to-result
     correlation mechanism — but each pending now subscribes to the
     query's AsyncGenerator filtered by message id.
3. Map every callback's old payload to the SDK's typed equivalent:
   - `onResult(sessionKey, event, entry, pending)` → fires on
     `SDKResultMessage`. Same shape (just typed).
   - `onStreamChunk(sessionKey, partialText, entry)` → fires on
     `SDKAssistantMessage` (or `SDKPartialAssistantMessage` for
     finer-grained streaming). Polygram's stream-reply primitive
     keeps its current API.
   - `onToolUse(sessionKey, toolName, entry)` → fires on
     `SDKAssistantMessage` containing `tool_use` blocks. Same.
   - `onAssistantMessageStart` → fires on a new top-level
     `SDKAssistantMessage` (id transition). Same semantic, cleaner
     trigger because the SDK already separates messages.
4. Implement `canUseTool` callback that calls into the existing
   `lib/approvals.js` store — replacing the `bin/approval-hook.js`
   IPC round-trip.

**Exit criteria for Phase 1:** every existing process-manager test
file passes (some will need fake-proc → fake-query rewrites in the
test harness, but assertions stay the same). No polygram.js changes
yet — the new pm presents the same API.

### Phase 2 — Wire features that the SDK unblocks (1 day)

These were deferred to 0.7.5 / 0.7.6 with the architecture caveat;
the SDK migration is the place where they land cleanly.

1. **D — mid-turn steer**: a new pm method `pm.steer(sessionKey,
   text)` that forwards via `query.streamInput({ priority: 'now',
   shouldQuery: false })`. polygram.js exposes this via a `/steer`
   slash command (or a natural-language trigger like "wait, also..."
   detected by intent classifier).
2. **E — clean interrupt**: `pm.interrupt(sessionKey)` calls
   `query.interrupt()`. polygram.js's `/stop` and "стоп" handler
   switches from `proc.kill()` + respawn to `interrupt()` — which is
   faster (no respawn cold-start) and keeps session state for the
   next message.
3. **F — typed telemetry**: drop the per-message-id usage Map +
   sumUsage workaround. Subscribe to `ModelUsage` directly from the
   typed event stream. Same `turn_metrics` table, same insert
   shape — just typed inputs.
4. **getContextUsage live warnings**: at end-of-turn, if
   `getContextUsage().percent > 0.85`, surface a "context window 85%
   full — `/compact` to free up" hint to the user.

**Exit criteria for Phase 2:** D, E, F all working on spike; new
slash commands tested; live context warning shown.

### Phase 3 — Migrate polygram.js to use the new pm features (1 day)

Polygram-side changes that consume the new pm capabilities:

1. `/stop` and "стоп" handlers call `pm.interrupt(sessionKey)`
   instead of `markSessionAborted` + `proc.kill()`.
2. Add `/steer` slash command + natural-language interception (out
   of scope for this plan — gated on UX decision).
3. Drop the `requestRespawnForSession` path for `/model` / `/effort`
   changes; replace with `pm.setModel(sessionKey, model)` etc.
4. Remove `bin/approval-hook.js` and the IPC plumbing for it.
   `lib/approvals.js` gets called directly from the canUseTool
   callback inside pm.

**Exit criteria for Phase 3:** all existing slash commands work,
including `/stop`, `/model`, `/effort`, `/permission-mode`,
`/approvals`, `/pair-code`, `/status`, `/logs`. None of them spawn
fresh claude processes anymore.

### Phase 4 — Drop deprecated paths (½ day)

Once Phase 3 is green:

1. Delete `lib/process-manager-cli.js` (the kept-for-reference
   rollback copy).
2. Delete `bin/approval-hook.js` and remove its hook config from
   `commands/` and the spawned env.
3. Remove `CLAUDE_BIN` env var support and its docs (the SDK module
   replaces the binary path).
4. Drop the `--no-chrome` / `--chrome` CLI flag passing — chrome is
   configured via `SdkOptions.mcpServers` now if at all.
5. Update README, AGENTS.md if any, and the `polygram-deploy` skill
   to mention "0.8.0+ uses SDK".

**Exit criteria for Phase 4:** `npm test` green, no dead code,
README accurate.

### Phase 5 — Soak (1 week, in production)

Goal: ship 0.8.0 to one bot first, watch for regressions, then
roll to all bots.

1. Bump to `0.8.0-rc.1` (NOT `0.8.0`). Publish to npm.
2. Deploy `0.8.0-rc.1` to **umi-assistant only** (lower-traffic bot).
   Leave shumabit on `0.7.6`.
3. Monitor for 7 days:
   - turn_metrics rows still arrive (telemetry path unchanged).
   - No "Hit a snag" replies in transcripts (errors handled).
   - `/stop` works.
   - Voice transcription works.
   - Stickers / reactions work.
   - Approval flow works (test by triggering an approval-required tool).
   - Memory plugin works (memsearch hook fires, daily logs written).
   - All cron-triggered jobs work (they go through the IPC interface
     which is unchanged).
4. If clean for 7 days: bump to `0.8.0`, deploy to shumabit. Soak
   another 3 days.
5. If any regression: rollback to `0.7.6` via
   `npm i -g polygram@0.7.6 && launchctl kickstart -k
   gui/503/com.shumabit.claude-sessions`. Document the regression as
   a known issue, fix on `main`, retry RC.

**Exit criteria for Phase 5:** 10 days of clean production with no
rollback needed → cut `0.8.0` final, archive this plan as the
historical record.

## Risk register

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| SDK doesn't expose feature X we depend on | Medium | High | Phase 0 spike is the gate. If a feature is missing, defer or build on top of `child_process` SDK internals. |
| Memsearch hook stops firing | Low | Medium | Verify in Phase 0 spike that `UserPromptSubmit` hooks fire from SDK invocations. They should — settings.json is loaded the same way. |
| Approval flow breaks | Medium | High | canUseTool semantics differ from PreToolUse hook (in-process vs subprocess). Phase 1 tests must cover the approval path explicitly. |
| Resume-by-session-id behaves differently | Medium | Medium | Phase 0 spike verifies; if the SDK uses a different session format than the CLI, write a one-time migration tool to convert existing session ids. |
| Performance regression (more node memory) | Low | Low | Each Query is in-process so memory grows with active chats; LRU cap (10 today) bounds it. Monitor RSS during Phase 5 soak. |
| `streamInput` priority semantics differ from OpenClaw's `steer` | Medium | Low | Validate in Phase 0 spike. If different, document the difference; users won't notice until they try Phase 2's D feature. |
| OAuth-in-process needs scopes our user doesn't have | Low | Medium | Defer the OAuth-in-process win to a follow-up; keep `claude /login` flow during 0.8.0 if it works. |
| Cron / IPC interface drifts | Low | High | IPC server is unchanged; cron callers don't touch process-manager. Verify end-to-end during Phase 1 tests. |

## What we are NOT changing (explicit non-goals)

To keep the migration tight and reduce regression surface:

- ❌ No new database schema (turn_metrics is from 0.7.6, stays).
- ❌ No new user-facing slash commands beyond /steer (gated on UX).
- ❌ No transcript-storage changes. We're sticking with our `messages`
  table; SDK's pluggable sessionStore is a future option, not a 0.8.0
  goal.
- ❌ No multi-provider support. We stay Anthropic-only. (The SDK
  doesn't even support multi-provider; that was OpenClaw's
  pi-coding-agent.)
- ❌ No removal of the `claude` CLI binary as a dependency. The SDK
  still spawns it under the hood; we just don't talk to it directly.
- ❌ No process-isolation refactor (one Node worker per chat). Each
  chat is one async iterator inside the daemon — same shape as today.
