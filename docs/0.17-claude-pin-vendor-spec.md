# Spec — Vendor the pinned claude CLI binary (stop the auto-pruner from killing cli chats) (#16)

Status: **DRAFT — for review then build.** Target: polygram 0.17.0.
Origin: recurring production outage — most recently 2026-06-22, Ivan's DM (cli) dead with "tmux session disappeared … claude exited before first captureWide" (claude exits in ~14 ms). Root cause: the hardcoded pinned claude version was deleted by claude's own auto-pruner.

## 1. Problem (verified)
- The cli/channels backend must spawn a SPECIFIC claude version. `lib/claude-bin.js` hardcodes `CLAUDE_CLI_PINNED_VERSION` (now `2.1.173`) and `verifyPinnedClaudeBin` resolves `~/.local/share/claude/versions/<pin>`; `polygram.js` sets `channelsClaudeBin = pinnedClaudeBin`.
- claude's auto-updater keeps only the **~3 newest** versions under `~/.local/share/claude/versions/` and **prunes** older ones. Once the pin falls out of the top 3 (185/183/181 present, 173 pruned), the pinned path is a dead file → every cli spawn dies in ~14 ms. SDK chats are unaffected (they use the bundled `node_modules/@anthropic-ai/claude-agent-sdk-<platform>/claude`, immune to the pruner — but it's a DIFFERENT, older version, 2.1.123, not validated for cli).
- **Fall-forward is unsafe:** the cli backend reads version-specific TUI internals (banner ASCII, READY hint, trust/dev-channel dialog wording, MCP-init order — "none a stable public contract", claude-bin.js). Each pin bump is re-validated via `tests/e2e-channels-real-claude.test.js`. A newer-but-unvalidated version can silently break the startup-gate / channel flow.
- **Reinstall-only treadmills:** `claude install <pin>` works for a specific version (restores it), but the NEXT claude auto-update prunes it again. Not durable.

## 2. Design — polygram vendors (owns a copy of) the pinned binary
polygram keeps its own copy of the exact pinned binary in a persistent, polygram-owned location the pruner never touches, and the cli backend spawns from THERE.

### 2.1 Vendor location
`~/.polygram/claude-bin/<version>` (e.g. `~/.polygram/claude-bin/2.1.173`). Persistent across both polygram reinstalls (`npm i -g` replaces the package dir, not `~/.polygram`) AND claude prunes. One file per pinned version. (Honor `CLAUDE_CONFIG_DIR`/a config override for the base dir if set; default `~/.polygram`.)

### 2.2 Resolution (`lib/claude-bin.js`, boot)
New `ensureVendoredClaudeBin(version)`:
1. `vendored = ~/.polygram/claude-bin/<version>`. If it exists + `X_OK` → return it. (Steady state — fast, no I/O beyond a stat.)
2. Else OBTAIN it, in order:
   a. `src = ~/.local/share/claude/versions/<version>` — if present + executable, **copy** `src → vendored` (preserve mode; atomic: copy to `vendored.tmp` then rename).
   b. Else run `claude install <version>` (bounded timeout), then copy from `src` as in (a).
   c. Else → return `{ ok:false, reason }` (loud, operator-actionable) — cli chats fall back per existing factory behavior; do NOT crash the daemon.
3. GC: remove any `~/.polygram/claude-bin/*` whose name ≠ the current pin (keep only the live version).
4. `polygram.js` uses `ensureVendoredClaudeBin(CLAUDE_CLI_PINNED_VERSION)` for `pinnedClaudeBin`/`channelsClaudeBin` instead of `verifyPinnedClaudeBin`.

Once vendored, the binary is immune to the pruner forever — no network, no re-install, no fall-forward. A pin bump (new release) → new version not yet vendored → boot copies/installs it once → GC drops the old.

### 2.3 Why not the alternatives
- Bundled SDK claude (node_modules): wrong/older version (2.1.123), not cli-validated, and replaced on every polygram `npm i`.
- Disable claude's auto-updater box-wide: stops Ivan's interactive claude updates too; a global side-effect we don't own.
- Reinstall-on-missing only: treadmills (re-pruned each claude update).

## 3. Failure modes / edge cases
- **Copy interrupted / partial** → atomic tmp+rename; a partial `.tmp` is never spawned; re-vendored next boot.
- **`claude install <pin>` fails** (network / version no longer served): only matters on FIRST vendoring of a pin; once vendored it never needs the source again. If it fails on first vendor → `{ok:false}` + loud warn + cli→SDK fallback (no crash).
- **Disk**: ~250 MB per pinned version; GC keeps exactly one. Pre-check free space; warn (don't fail) if low.
- **Permissions / mode bit**: copy with `fs.copyFileSync` + `fs.chmodSync(0o755)`; verify `X_OK` post-copy.
- **Cross-platform**: the source binary is already platform-correct (linux-x64 on the VPS, darwin-arm64 on the Mac); copy preserves it. No platform logic needed.
- **Concurrent boots** (two bots starting): vendoring is idempotent (stat-first); tmp+rename avoids a torn file; a redundant copy is harmless.
- **Running daemon already on a dead pin** (the incident): boot re-vendor fixes it on next restart; the interim `claude install <pin>` handles the live case without restart.

## 4. Test plan (red→green)
- `ensureVendoredClaudeBin`: vendored present → returns it (no copy). Vendored missing + source present → copies (mode preserved, X_OK), returns vendored. Vendored + source both missing → attempts install (stub), then copy; install-fails → {ok:false} (no throw). GC removes non-pin vendored dirs/files.
- atomicity: a pre-existing `<version>.tmp` doesn't get returned; interrupted copy leaves no spawnable partial.
- polygram boot wiring: `channelsClaudeBin` points at the vendored path; cli factory spawns it.
- regression: `verifyPinnedClaudeBin` behavior preserved for any other caller / the {ok:false} fallback path.
- (manual) e2e: `tests/e2e-channels-real-claude.test.js` against the vendored binary.

## 5. Rollout
0.17.0 → npm → VPS (install → rebuild better-sqlite3 → restart; first boot vendors 2.1.173 from the now-present ~/.local/share copy). shumorobot via the upgrade script. After deploy, `claude`'s pruner removing 2.1.173 from ~/.local/share no longer affects polygram (it spawns the vendored copy). Verify: delete-simulate (`mv` the ~/.local/share/<pin> aside) and confirm cli chats still spawn from the vendored copy.

## 6. Out of scope
- Auto-bumping the pin / auto-validating new claude versions (still a manual, e2e-gated release step).
- SDK backend binary management (already immune).
