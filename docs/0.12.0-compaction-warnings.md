# 0.12.0 — Per-chat compaction warnings (CLI/channels backend)

## The problem

On the CLI/channels backend (`pm: 'cli'`), when Claude's context window fills
up the TUI **auto-compacts** mid-turn. Compaction interrupts the in-flight
turn (Claude pauses to summarize and re-initialize), which is disruptive on a
long task.

> **Correction (rc.14):** an earlier framing of this doc claimed compaction
> *detaches the bridge* — that the `server:polygram-bridge  no MCP server
> configured with that name` banner meant the reply channel had died. That was
> a **misdiagnosis**. That banner is a **benign, cosmetic line** that
> `--dangerously-load-development-channels` + `--strict-mcp-config` prints on
> *every healthy* session — the channel keeps working (verified with a real
> claude e2e: `tests/e2e-channels-real-claude.test.js`). The "mid-turn detach"
> was actually rc.11's pane matcher **false-firing on that benign banner and
> killing healthy turns**; rc.14 removed the matcher. So rc.11/rc.12's
> "recovery" machinery reacted to a false signal. They remain only for genuine
> **socket-close** disconnects.

This feature still earns its keep: a proactive warning lets the user
`/compact` or `/new` at a natural break instead of having an auto-compaction
interrupt a turn — the same context-management UX the SDK backend already
offers. It does **not** prevent any "bridge drop" (there was none).

## What it does

Two messages, both **opt-in per chat** and **off by default**:

- **Proactive** — at turn-end, polygram samples the context occupancy from the
  session transcript. When it crosses the chat's threshold (default **75%**),
  it posts once:
  > 📚 Heads up — this chat's context is ~80% full. To avoid an auto-compaction
  > that can interrupt a turn, run `/compact` (optionally with a hint) at a
  > natural break — or `/new` for a fresh start.

  Warned once per "climb"; re-armed after the context drops (PostCompact).

- **Reactive backstop** — if auto-compaction fires anyway (`PreCompact`,
  `trigger: auto`), it posts:
  > 🗜️ Auto-compacting now — context filled up. If this turn goes quiet,
  > please resend.

A **manual** `/compact` (the user's own deliberate action) never warns.

## How context is tracked

Not by transcript file size (it's an append log — it never shrinks on
compaction). polygram reads the **last main-thread assistant `usage`** from the
transcript JSONL once per turn-end (on the `Stop` hook, which carries
`transcript_path`) and computes
`(input_tokens + cache_read_input_tokens + cache_creation_input_tokens) /
window`. Subagent (sidechain) frames are skipped. See `lib/context-usage.js`.

The "imminent" edge comes from the `PreCompact` hook (now registered alongside
`PostCompact`), whose `trigger` field distinguishes `auto` from `manual`.

## Config

Per-chat or per-topic (topic wins), under `config.chats[id]` (or `topics[t]`):

```jsonc
// shorthand: enable at the 75% default threshold
"compactionWarnings": true

// or custom threshold (1–99)
"compactionWarnings": { "enabled": true, "thresholdPct": 80 }
```

Omitted / `false` / object without `enabled: true` → **off**.

Requirements:
- CLI/channels backend (`pm: 'cli'`) — the SDK backend already surfaces its own
  context-% hint.
- The bot must allow the `/compact` and `/new` slash commands (it proposes
  them).

## Limits

This **reduces** mid-turn auto-compactions; it doesn't eliminate them. If the
user ignores the proactive warning and keeps chatting, claude will still
auto-compact at its own threshold — at which point rc.11/rc.12 recovery + the
reactive message take over. polygram cannot make Claude's compaction preserve
the channels bridge (that's a Claude Code research-preview behavior); it can
only warn ahead and recover after.

  (proactive %, reactive resend) threaded under the topic.
