## The tier decision: **Tier 2C — fold-seen by explicit reply contract**

Q-A=NO kills Tier 1 (no per-fold UPS). Q-B-as-incidental-echo is unreliable-by-construction
(single `turn_id` field, claude echoes the trigger). But the spike surfaced a better mechanism
than the design's Tier 2 inference: **claude demonstrably sees folded envelopes and can report
their turn_ids on request.** Since the reply/edit_message/ask tool schemas are polygram's own
surface (the bridge defines them; the `ask` tool is precedent for extending them — this does NOT
touch Anthropic's channels notification protocol, so the design's non-goal stands):

- Add an optional `consumed_turn_ids: string[]` arg to the bridge `reply` tool + one
  system-prompt line ("in every reply, set consumed_turn_ids to the turn_id of every <channel>
  message you are answering or have absorbed since your last reply").
- D2's `seen/resolved` for `autosteer`/`edit-fold` entries comes from this contract field
  (validated against the ledger's known-uuid set, same anchored discipline as the UPS parser).
- The runtime echo-anomaly guard from the design applies unchanged: folds whose entries are
  never acknowledged park as `fold-suspected`; an anomaly-rate threshold auto-disables fold
  redelivery + alerts. A forgotten echo can therefore delay/park, never double-answer by itself
  (redelivery still requires the full drop window: trigger-cycle end + next-cycle start + grace).
- `primary` entries keep UPS-seen (Q1) — unchanged from the design.
- Preflight gains two assertions per binary bump: UPS envelope parseability (Q1) and the
  consumed_turn_ids contract behavior (a fold run asserting the folded id appears).

Implementation deltas vs the design as written: the D2 tiering paragraph's "Tier 2" inference
(reply-echo + next-cycle UPS content) is **superseded by the contract field**; everything else
(drop window, supersession, redelivery constraints, watchdog regimes) is unchanged. The P3 TDD
list gains: fold acknowledged via consumed_turn_ids → `resolved`, never redelivered; fold with
missing acknowledgment → `fold-suspected`, parked, telemetry only.

## Residual unknowns (tracked, none blocking)

1. Q3 for a *non-folding inject* specifically: not provoked in 2 runs (folds dominated, as
   F#24 predicts). The Phase-D evidence covers the same pickup mechanics; the drop window's
   `next-cycle-start` term doesn't depend on which shape the pickup takes.
2. consumed_turn_ids adherence rate is a model behavior — measured in prod by the ledger
   telemetry itself (the echo-anomaly guard is the containment, per the design's R4).
3. Compaction-adjacent Stop behavior unobserved (0 compactions in 30d of local data) — the
   `stopHookActive` gate + activity-cancel grace bound the blast radius if one ever fires
   mid-cycle.
