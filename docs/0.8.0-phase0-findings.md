## Architectural decisions resolved

1. **Streaming model: cumulative `SDKAssistantMessage`** (gate 3 PASS). Pm rewires `extractAssistantText` to consume the new shape; `lib/stream-reply.js` cadence preserved.

2. **Long-lived Query per chat** (gate 1 PASS). pm holds one Query per sessionKey; `inputController` is the writable end of an `AsyncIterable<SDKUserMessage>` open for the chat lifetime.

3. **`/effort` no longer needs respawn** (gate 19 PASS). v4 plan seam A canonical resolution: **DELETE `requestRespawn`/`onRespawn` machinery**. Phase 3 step 3 uses `pm.applyFlagSettings(sessionKey, {effortLevel})`.

4. **`Options.env` is SHADOW** (gate 33 PASS). buildSdkOptions explicitly includes every env var polygram needs.

5. **`Query.close()` is fast** (gates 30, 32 PASS). Shutdown bounds are non-issues; today's 100ms exit timeout is safe.

6. **No `includePartialMessages: true`** (gates 3, 4). Use cumulative assistant messages; simpler.

7. **Resume across separate Query() calls works** (gate 26 PASS). polygram's `claude_session_id` table semantics carry forward unchanged.
