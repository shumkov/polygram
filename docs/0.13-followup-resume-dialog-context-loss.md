# #15 follow-up — session-resume dialog: silent context loss + dropped reply

> Handoff from the config-commands session (2026-06-10). REPRODUCED with real claude.
> Two distinct, confirmed cli-session-lifecycle bugs that the rc.36 `/model` reload-on-drift
> fix exposed. The `/model` fix itself is correct; its "conversation kept" guarantee rides on
> `--resume` working, which these bugs break. Owner: the #15 channels-lifecycle session.

## BUG 1 — the gate silently summarizes (context-degrading default)
`lib/process/cli-process.js`:
- `SESSION_AGE_PROMPT_RE = /Resuming the full session[\s\S]*Resume from summary/i` (:99)
- gate catalog: `{ name: 'session-age', regex: SESSION_AGE_PROMPT_RE, key: 'Enter' }` (:847) /
  `{ ..., action: 'enter' }` (:101)

`Enter` confirms the **pre-selected option 1 = "Resume from summary"**. So EVERY aged-session
resume silently drops the full conversation for a summary — the user gets a context-degraded
agent with no signal. To pick **"2. Resume full session as-is"** the gate would have to send
`Down Enter` (or `2 Enter`), not bare `Enter`.

Design questions:
- Should polygram pick **full-resume** (preserve continuity, higher usage), keep **summary**
  (cheaper, lossy), proactively **`/compact`** before sessions reach this size, or make it a
  per-chat/topic config? (Music is a long-running curation session — continuity matters there;
  a quick Q&A chat may prefer summary.)
- The 115.8k-token / 6h threshold is claude's, not polygram's — polygram can't see it coming
  except by watching for this exact prompt. Is a proactive compaction policy better than
  reacting to the dialog? (See the existing `compactionWarnings` work on the Music topic.)
- **Model-switch angle:** rc.36 `/model` reload-on-drift respawns with `--resume`, so a `/model`
  change on ANY aged session triggers this dialog → summary-resume → the "conversation kept"
  claim is silently violated. This is the direct coupling to the config-commands fix.

## BUG 2 — dropped reply on resume-fail → fresh-retry (higher severity)
When claude EXITS during `--resume` (prod 2+2: "tmux session disappeared" at 32s, before the
~58s dialog even rendered in repro — timing varies) and polygram retries in a **fresh** session,
the fresh turn runs and calls `reply` (turn_id X) but the reply is **never delivered**. Suspect:
turn_id ↔ pending-turn correlation (`cli-process.js ~1201`) desyncs across the spawn swap — the
reply's turn_id doesn't match a pending turn after the resume-fail reset, so it's dropped. Net:
**claude produced a correct answer and the user silently got nothing.** This is the bug to kill
first — a dropped answer is worse than a degraded one.

## RESOLVED 2026-06-11 — see `docs/0.13-resume-dialog-fix-spec.md`

Investigated, spec'd, adversarially reviewed (approve-with-changes; all
findings folded), implemented TDD red→green, real-claude E2E green.

- **BUG 2 (dropped reply) — root cause was NOT correlation desync.** Prod
  events prove rc.36's correlation worked end-to-end (`cli-input-acked` →
  reply ok → `reply_count:1 attributed:seen`). The reply died in the PARSE
  layer: `\p{Emoji}` matches digits (keycap bases), so "4" became a solo
  "reaction" with empty text (smoking gun: `channels-tool-dispatcher-
  reactions-dropped {"dropped":["4"]}`), and the cli backend never passed
  `sourceMsgId`, so ALL solo reactions dropped with no target. Fixed both
  (parse guard incl. digit+VS16; ledger-resolved sourceMsgId with
  first-reply-only quoting).
- **BUG 1 (silent summarize) — worse than suspected: the pre-selected option
  literally runs `/compact`.** Binary-verified mechanics + threshold env vars
  (`CLAUDE_CODE_RESUME_THRESHOLD_MINUTES`/`…_TOKEN_THRESHOLD`, defaults
  70min/1e5). Fixed: dialog suppressed per-process at spawn (huge minutes
  threshold in tmux envExtras → always full resume, "conversation kept"
  holds); belt-and-braces Down,Enter (full resume) + `session-age-dialog-
  fallback` telemetry in BOTH the startup gate and the mid-turn watchdog.
- **The ~32s resume death** (claude exits during `--resume` load) is the known
  upstream channel-bind race — evidence recorded in the spec (3 deaths
  clustered at ~32s incl. UMI 2026-06-11 double-strike), containment =
  rc.25 auto-retry + history-preload, tracked in `docs/0.12.0-known-issues.md`.
  Soak metric added: `history-preloaded session_source:"fresh"` rate on
  resumable sessions measures actual context retention.
