# 0.10.0 — tmux concurrency: solution design

> Companion to `0.10.0-tmux-concurrency-problem.md`. Synthesises a
> four-agent parallel investigation (turn-state machine, JSONL
> parser, paste/handler concurrency, test coverage). The four audits
> ran independently and **converged on the same root cause and the
> same fix** — that convergence is the main evidence this design is
> correct.

## Root cause (unanimous across all four audits)

**Attribution is reconstructed, not recorded.** polygram knows, at
paste time, exactly which Telegram `msgId` each message is. It then
*discards that binding*, pastes raw text into the TUI, and tries to
*recover* the binding later by content-matching JSONL events against
accumulators. Content matching is lossy on four independent axes:

1. The TUI **concatenates** pastes landing close together → one
   `user-message` contains multiple messages' text; the boundary is
   gone.
2. The TUI **folds vs splits non-deterministically** (FOLD vs
   NEW-TURN) → the reply count is unknown.
3. **Short messages are substrings of each other** — `"da"` ⊂
   `"das"` ⊂ `"b / da / das"` — so `ev.text.includes(content)`
   matches multiple pendings → duplicate + cross-attribution.
4. JSONL events **arrive reordered** under burst write load → the
   "user-message before result" assumption breaks.

The four accumulators — `_turnState`, `pendingQueue`,
`_pendingAutosteers`, `_extraTurnState` — are four partial
projections of one missing object: **an ordered ledger of turns,
each with a stable id, a set of owning msgIds, and a state.** Every
rc.7→rc.19 fix added another ordering heuristic instead of recording
the binding; the heuristics now contradict each other (exact-match
vs substring; `_turnState`-first vs `_extraTurnState`-first). No
patch to matching can restore information discarded at paste time.

## Verified facts the investigation surfaced

These were confirmed against real JSONL in
`~/.claude/projects/-Users-ivanshumkov/` and the production DB:

- **`parseLine` is stateless per-line, but the CLI writes one
  logical assistant message across many JSONL lines — each carrying
  `stop_reason`.** `session-log-parser.js` fires a `result` event
  for *every* such line. Thinking-only / tool-only lines produce
  **empty-text `result`s that resolve a turn before its real text
  arrives**. → *Empty-turn is reproducible with ZERO concurrency.*
- **The FOLD-detection path is dead code.** It keys on an
  `attachment.type === 'queued_command'` shape that **does not exist**
  in real JSONL. The actual fold signal is an unparsed
  `type: 'queue-operation'` event.
- **`last-prompt` fires when a prompt is *registered*, not when a
  turn *ends*** — and in one variant carries no `lastPrompt` field.
  It is misused as a turn-completion signal.
- **`inFlight` is the wrong predicate.** It is set deep inside
  `send()`, after spawn (~11 s) and after `stdinLock`. The
  autosteer-vs-primary decision (`autosteer.js` `willAutosteer` /
  `tryAutosteer`) reads it far earlier → a 3-message burst is
  mis-classified as 3 primary turns instead of 1 primary + 2
  autosteers (the 12:59 trace). rc.18 fixed one instance
  (`getOrSpawn`); the decision race remains.
- **The async-lock makes one paste atomic but does not stop two
  *consecutive* pastes from concatenating** — the 50 ms post-Enter
  drain is a timing guess, not a barrier.

## Failure-mode → cause map (all seven, 12:59 trace)

| Mode | Cause |
|---|---|
| Empty turn | empty-text `result` from a non-terminal line; or a primary `_turnState` starved while `_extraTurnState` is unflushed; or `result` arriving before its `user-message` and being dropped |
| Cross-attribution | substring match pops the wrong pending; `_extraTurnState` is one text buffer with a list of msgIds |
| Duplicate reply | the flush loop emits the shared `_extraTurnState.text` once per msgId |
| Echoed input | capture-pane fallback diffs the pane and returns the user's own echoed input line as "reply" |
| Empty out-message | empty-`_extraTurnState` flush guard strands a real reply; or a turn is starved entirely |
| Canned strings | paste concatenation hands the *agent* a garbled blob; it emits "No response requested." |
| Stuck reactions | `_extraTurnState`'s `result` never arrives recognisably → `extra-turn-reply` never fires → reactor-clear + typing-loop teardown never run |

## The solution — record attribution, don't reconstruct it

Seven changes. (1)–(3) are the core; (4)–(7) fall out once the core
lands.

### 1. Correlation token in every paste

Embed a unique per-message token in each pasted prompt, **inside the
`<polygram-info>` block polygram already wraps every inbound in**
(the agent is already instructed to ignore that block). The JSONL
`user-message` then carries the token **verbatim**. Attribution
becomes an **exact id lookup**:

- immune to concatenation — a concatenated `user-message` contains
  *N* tokens, telling you exactly which N turns the TUI merged;
- immune to substring collisions — tokens are unique;
- immune to reorder — the token travels with the event.

This single change deletes the entire substring-matching class
(L5/L14 saga, `_pendingAutosteers` content matching, the
`pastedPromptOneLine` heuristic).

### 2. Turn ledger replaces the four accumulators

One ordered, append-only structure: a list of `Turn` records.

```
Turn {
  turnId            // monotonic local id — the authority
  token             // the correlation token embedded in the paste
  msgIds: number[]  // every Telegram msgId this turn answers (1+)
  kind              // 'primary' | 'autosteer'
  state             // 'queued' | 'pasted' | 'streaming' | 'done' | 'failed'
  text              // accumulated reply
  resolve / reject  // promise settlers for the owning send()/extra-turn
}
```

`_handleSessionEvent` extracts token(s) from each `user-message`,
looks up the `Turn`(s), routes `assistant-chunk`/`result` to the
turn its `user-message` introduced. The handler never guesses from
"which accumulator is non-null". `pendingQueue` becomes the ledger's
`state:'queued'` slice — no separate array, no positional
head/non-head ambiguity. A `user-message` with N tokens = an
explicit, unambiguous fold of N turns: deliver the shared reply to
the union of their msgIds **once** (dedup by msgId).

### 3. Stateful JSONL aggregator

Replace per-line `parseLine` with a `SessionEventAggregator` that:

- **coalesces assistant lines by `message.id`** — emits one logical
  assistant message, and fires `result` only on the *true* turn end
  (terminal `stop_reason` on the final line of that message id), not
  on every intermediate line;
- **parses `type:'queue-operation'`** — the real FOLD signal —
  replacing the dead `queued_command` path;
- **forwards `parentUuid` / `promptId`** correlation metadata so the
  ledger never has to guess ordering.

This alone fixes the zero-concurrency empty-turn bug and is the
lowest-risk, highest-isolation phase.

### 4. Committed-intent latch (not racy `inFlight`)

The autosteer-vs-primary decision and the ledger append + paste
happen inside **one per-session critical section**. The first
handler to acquire it for a session with no live turn becomes the
primary and appends its turn; every later handler sees a committed
turn and autosteers. Decision is by **arrival order via the lock**,
not a raced `inFlight` snapshot.

### 5. Paste gating on JSONL confirmation

A paste does not release the next waiter until the JSONL tail has
emitted the `user-message` (or `queue-operation`) for that paste,
with a bounded timeout. Converts the 50 ms drain guess into a real
barrier — two pastes can no longer concatenate, so the agent never
receives a garbled blob.

### 6. capture-pane demoted to liveness only

Reply text comes **exclusively** from JSONL keyed to a turnId.
capture-pane is a timeout/liveness signal only — it never delivers
reply text. A turn with no JSONL text within timeout **fails loud**
with an explicit error result, never with echoed pane content. Kills
the echoed-input mode and the banner mode (L1) outright.

### 7. Single reaction owner + one ordering authority

`autosteeredRefs` becomes the sole authority for an autosteered
msg's reaction state; all reaction writes for a msgId serialise on a
per-msgId lock. Turn-ordering has exactly one FIFO authority (the
ledger inside `TmuxProcess`) — drop polygram's separate `stdinLock`.
Stale turns are swept at turn-completion: any ledger turn with no
JSONL correlation after a grace window fails explicitly (reactor
clears). No turn — and no reaction — can leak.

## Why this satisfies the five invariants

- **Completeness** — every msgId is attached to exactly one `Turn`;
  a turn delivers text or fails loud; the sweep prevents leaks.
- **Attribution** — tokens are injective and survive
  concatenation/reorder; replies go to the exact `Turn.msgIds`.
- **No spurious output** — text comes only from JSONL keyed to a
  turnId; capture-pane can't echo input; fold delivers once.
- **Reaction fidelity** — explicit turn states + sweep guarantee the
  reactor-clear signal always fires.
- **Agent never sees garbage** — paste ordering is decided under the
  session lock; a deliberate fold (multi-token) is intentional, not
  garbled.

## Phased implementation plan

| Phase | Work | Risk | Independent? |
|---|---|---|---|
| **1** | Stateful JSONL aggregator + `queue-operation` parsing (solution §3) | low | yes — ship alone |
| **2** | Correlation token + turn ledger (§1, §2) | high — core rewrite of `tmux-process.js` turn machine | needs phase 1 |
| **3** | Committed-intent latch + paste gating (§4, §5) | medium | needs phase 2 |
| **4** | capture-pane demotion, reaction owner, lock consolidation (§6, §7) | medium | needs phase 2 |

**Phase 0 (do first):** validate the correlation token against the
real TUI — confirm the agent reliably ignores it and the JSONL
`user-message` reproduces it verbatim *after* the
`MULTILINE_SEPARATOR` (`\n → ' / '`) transform. The token is the
linchpin; if the TUI mangles it, the design needs adjustment.

> **Phase 0 — VALIDATED (2026-05-16, claude CLI 2.1.142).** Spike
> `scripts/spikes/correlation-token-tui.mjs`, 3 scenarios / 18
> assertions, all green. Confirmed:
>
> - A `pgm-corr-<hex>` token embedded in the multi-line
>   `<polygram-info>` block survives the paste → `MULTILINE_SEPARATOR`
>   → JSONL `type:'user'` round-trip **byte-for-byte**, both as an
>   opening-tag attribute (`corr-id="…"`) and as a child line
>   (`<corr-id>…</corr-id>`). The token is newline-free, so the
>   `\n → ' / '` transform never splits it.
> - The agent **ignores** the token — it is never echoed, mentioned,
>   or treated as an instruction.
> - Concatenation immunity holds: two pastes carrying distinct tokens
>   each yield exactly one verbatim token in the JSONL. (Observed: the
>   TUI emitted two separate `user-message` lines; the design is
>   immune either way — N tokens in one line = N folded turns.)
>
> Token shape `pgm-corr-<seq><rand><time-hex>`: `[a-z0-9-]` only — no
> whitespace, no XML metacharacters, no C0/DEL bytes (`TmuxRunner.sanitize`
> would strip those), no newline. **Phase 1 may proceed.**

## Test / reproduction plan

The real-claude spike is non-deterministic on FOLD vs NEW-TURN, so
it cannot be a reliable *red* proof. Primary red/green proof is
**deterministic unit tests** with hand-written JSONL (the
`tmux-process-jsonl.test.js` style):

- **B1** — concatenated `user-message` carrying multiple tokens →
  assert each distinct message gets a distinct reply, none
  duplicated. Red today (shared-text fan-out).
- **B2** — `result` arriving before its `user-message` → assert the
  turn still delivers non-empty text. Red today (result dropped).
- **B3** — assistant text equal to the user's input → assert the
  delivered reply ≠ the sent prompt. Red today (no echo guard).
- **A2** — strengthen the rc.18 `getOrSpawn` test: actually `send()`
  through a gated spawn and assert turn 2 is non-empty (the current
  test pins the *await* but never the *symptom*).

Plus a spike harness change: `setupRealTui` must support
`sendDuringSpawn` (don't `await start()`) so the 09:24 and 12:59
traces — messages arriving *during* the ~11 s spawn — are
expressible. Two spike scenarios replay the traces and assert the
five invariants as the real-TUI regression guard.
