# 0.12.0 — Context & token observability spec

Status: design, not yet scoped to a release. Filed 2026-05-28 as a follow-up to the SessionStart pairing spec (see [`0.12.0-session-start-pair-spec.md`](./0.12.0-session-start-pair-spec.md)) after inspecting [moshi-hooks](https://github.com/rjyo/moshi-hooks) source confirmed claude's hook stdin payload carries `transcript_path` — enabling at-rest transcript reads for context-window and last-message observability.

This spec assumes the pairing spec's hook plumbing (relay binary, IPC op, `recentSessions` map, `install-hooks` CLI) is already in place. It adds the user-visible observability layer on top.

## What the operator gets

Reactive query:

```text
me> /context
bot> 📊 ~/projects/foo · sonnet
     142,331 / 200,000 tokens · 71% of window
     last session: 8e1c… · started 2h 18m ago
     last message: "I've reviewed the PR and added comments on..."
```

Proactive notification when a turn ends near the limit:

```text
bot> ⚠️ Claude is at 86% context (171k / 200k). Auto-compact will fire
     near 92%, or run /compact now to control the cut.
```

Two user-visible behaviors: one query command, one threshold push.

## How it works

Polygram listens for two hooks (in addition to the SessionStart hook from the pairing spec):

- **`SessionStart`** (already wired by pairing spec) — stashes `{cwd, session_id, transcript_path, model}` in `recentSessions`. This spec extends the stored shape to include `transcriptPath` explicitly.
- **`Stop`** (and `SubagentStop`) — same relay + IPC path, distinct op (`op: 'hook-stop'`). On receipt, polygram tail-reads `transcriptPath`, computes % usage, and if above the configured threshold pushes a notification to the chat paired to that cwd.

`/context` is a Telegram slash command in `lib/handlers/slash-commands.js`:

1. Look up the chat's `chatConfig.cwd` in `recentSessions`. If miss → reply `❌ No recent claude session for this chat's cwd. Run claude there to register.`
2. Tail-read the stored `transcriptPath` (last 10KB, parse newline-delimited JSON entries from the end backwards).
3. Find the most recent entry with `usage.input_tokens` → sum `input + cache_creation + cache_read` → divide by model's context window → percent.
4. Find the most recent entry with `role: "assistant"` → extract text from content blocks (string or `content[]` shape per moshi-hooks src/index.ts:175-186) → truncate to ~200 chars.
5. Render the response above.

The tail-read pattern (`src/index.ts:134-158` in moshi-hooks) is well-defined: bounded memory, fast, handles MB-sized transcripts gracefully. Lift the algorithm; the runtime details (Bun.file → fs.readSync) translate directly.

## Why hooks, not polygram's existing JSONL tail

Polygram's tmux backend already calls `getContextUsage()` mid-turn — but only for **in-flight sessions polygram itself spawned**. Two gaps this spec closes:

1. **Idle sessions are invisible.** After a turn resolves, polygram drops the pm reference. The transcript is still on disk, but polygram doesn't remember where. So `/context` between turns returns nothing today.
2. **Operator's terminal-run claude is invisible.** Polygram has no signal for sessions it didn't spawn. The whole point of querying "how full is my context" from Telegram is to know without switching to the terminal.

Hooks fire from every claude invocation regardless of who spawned it. SessionStart gives polygram a persistent `transcript_path` that survives turn boundaries and works for any claude on the host.

## Threshold notification design

**Threshold: 85% by default** (`config.bot.contextWarnThreshold = 85`).

Rationale:

- Claude auto-compacts around **92%** of the window. Auto-compact is opportunistic and sometimes summarizes context the user wanted to keep.
- 85% gives ~7 percentage points of warning — roughly one or two turns of work to decide between `/compact` (manual control) and letting auto fire.
- **50%** is too noisy. **90%** is too late (one large tool input can cross it).

**Deduplication**: track `lastWarnedAt[cwd]` in-memory. Only push once per session per crossing — once warned, don't re-warn until the % drops below threshold (compact) and crosses back up. Prevents spam if user does several near-limit turns in a row.

**Push target**: the Telegram chat paired to the cwd. Falls back to admin chat if no chat is paired to this cwd (rare but possible: operator ran claude externally, never paired the cwd to a chat). Skips push entirely if no chat AND no admin.

## Data model extension

Pairing spec's `recentSessions` map already exists. This spec adds two fields:

```js
recentSessions = new Map();   // key = realpath(cwd), value = {
  cwd:            '/Users/u/projects/foo',
  sessionId:      '8e1c…',
  transcriptPath: '/Users/u/.claude/projects/foo/abc.jsonl',   // NEW
  model:          'sonnet',
  observedAt:     1716938400_000,
  lastWarnedAt:   0,                                            // NEW — dedup
};
```

No new persistent storage. Same 30-min TTL, same 32-entry cap.

## Model → context-window mapping

Hardcoded for known models, fall back to 200_000:

```js
const MODEL_CONTEXT_WINDOWS = {
  sonnet: 200_000,
  opus:   200_000,
  haiku:  200_000,
  // Sonnet-with-1M-context variant — Anthropic may add a flag for this;
  // if so the hook payload's `model` field will distinguish it.
};
function contextWindowFor(model) {
  return MODEL_CONTEXT_WINDOWS[normalizeModelName(model)] || 200_000;
}
```

Configurable via `config.bot.modelContextWindows` if Anthropic ships variants with different sizes.

## New surface

Two commands:

| Command | Behavior | Auth |
|---|---|---|
| `/context` | Show % context-window used + model + session age + last message. Reads `transcriptPath`. | Paired chat only |
| `/tail` | Show just the last assistant message (truncated). Same tail-reader, returns step 4 only. | Paired chat only |

Plus one IPC op extension:

```text
op: 'hook-stop' → triggers threshold check + optional push notification
```

(The `op: 'hook-session-start'` op from the pairing spec already stashes `transcript_path` — this spec just consumes it.)

## What this design doesn't do

- **Doesn't show context for sessions that ran before hooks were installed.** No `transcript_path` in the map until SessionStart fires after install.
- **Doesn't track per-turn token deltas.** Only "current cumulative usage" at the most recent transcript entry. Per-turn would require parsing the whole transcript history — out of scope for the tail-read pattern.
- **Doesn't auto-trigger `/compact`.** The push is informational; user decides whether to compact manually, switch sessions, or accept auto.
- **Doesn't push for `SubagentStop`** by default — subagent context is bounded by parent, not directly relevant to the main-window usage. Configurable via `config.bot.warnOnSubagentStop`.

## Edge cases

- **Transcript file deleted between SessionStart and `/context`.** Hook fired, polygram has the path, file is now gone (operator wiped `.claude/projects/` or claude rotated it). Tail-reader catches `ENOENT`; reply: `❌ Transcript no longer on disk for ~/projects/foo — run claude there to refresh.`
- **No `usage` entries in the last 10KB.** Possible if the tail is all tool-use entries with no assistant turn yet. Expand to 50KB on retry; if still missing, reply: `🤷 Couldn't find usage data in recent transcript — try again after a model turn completes.`
- **Multi-line content in last assistant message.** Strip newlines, collapse whitespace before truncating to 200 chars. Telegram inline message readability.
- **Cache vs non-cache tokens.** Per moshi's pattern: sum `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`. All three count against the window.
- **`Stop` fires twice (Stop + SubagentStop in quick succession).** Same 5s debounce moshi uses — if `lastStopWarnedAt[cwd]` is within 5s, skip the second.

## Threat model

Same as pairing spec — `/context` and `/tail` only work for cwds the chat is paired to. The transcript file is read with polygram's process credentials (same as the operator's); no privilege escalation. No new exposure.

## Open questions

1. **Is `/tail` worth shipping?** It's ~20 LOC on top of `/context`. My recommendation: ship it — low cost, useful for "what was the last thing the agent said while I was AFK."
2. **Push threshold default — 85% right, or higher?** Calibratable after a few weeks of production observation. Operator can override via `config.bot.contextWarnThreshold`.
3. **`/context` from unpaired chat?** I.e. let any admin-chat user query context for ANY known cwd in the recent-sessions cache, not just the chat's paired one. My recommendation: paired only, for symmetry with `/use`. Keeps scope clean.
