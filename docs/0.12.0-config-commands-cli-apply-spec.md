# 0.12.0 — `/model` & `/effort` actually apply on the cli backend (+ honest `/config` card)

> **Status: spec for sign-off (not yet implemented).** Worktree `polygram-config-cmds`
> (branch `0.12.0-config-cmds`, off `0.12.0-cli-driver`). Ships bundled with the undeployed
> rc.34 content (multi-select checklist, post-submit progress) + edit-redelivery.

## The bug (verified on shumorobot rc.33, Music topic, 2026-06-10)

`/model opus` does **not** switch the running cli session. Transcript ground truth: session
`94340797` ran `claude-sonnet-4-6` for all 142 assistant messages (11:53→12:40 local), through
and after `/model opus`. The card + `turn_metrics` showed "opus" (polygram's *requested* config),
but the CLI never switched — claude's "Claude Sonnet 4.6" self-report was correct.

Two layers:
1. **Design limit:** `CliProcess` has no live `setModel`/`applyFlagSettings` — model & effort are
   spawn-time `--model` / reasoning flags. `/model` persists to `chatConfig` but the running session
   keeps its spawn-time model until a cold respawn.
2. **Dead honest-message branch:** `slash-commands.js:209-212/239-242` (Review F#10) was meant to
   say "*— applies on next /reset (channels)*" but checks `backendName === 'channels'`. 0.12.0
   renamed the backend to `'cli'` (`cli-process.js:203 this.backend = 'cli'`), so the branch never
   fires → the user gets the misleading "*I'll switch when I finish*" (which never happens).

`/reload` (slash-commands.js:144-154) already proves the in-place re-init path the F#10 comment
claims "channels lacks": `pm.kill` closes the proc but **preserves `session_id`** (only
`resetSession` clears it), so the next message resumes the SAME conversation under fresh spawn
flags. We build on that.

## Decisions (operator-confirmed 2026-06-10)

- **Auto-apply via reload** — `/model` & `/effort` on cli take effect on the user's next message,
  **conversation preserved**. In-flight turn → applies after it finishes.
- **Card shows the truth** — `/config` & `/model` card reports the actual *running* model when it
  differs from the configured one (`sonnet (running) → opus (pending)`), so it never lies again.

## Design — lazy reload-on-drift at spawn (approach II)

Chosen over eager-kill-at-`/model`-time because it matches the operator's mental model (card shows
`running → pending` until the next message), needs **no turn-end/idle listener** (minimal coupling
with the #15 lifecycle work), reloads exactly when needed (next dispatch), and reuses the proven
`kill` + `--resume` path. Eager mid-turn kill would interrupt the running turn; deferring via
`'idle'` listeners adds races.

### Part 1 — Reload-on-drift in `getOrSpawn` (the core)

- `CliProcess.start()` stores its resolved spawn values: `this.model`, `this.effort` (extract the
  existing precedence at cli-process.js:547-549 into `_resolveModel(opts)` / `_resolveEffort(opts)`
  so there's ONE source of truth, used by both `start()` and the drift check).
- New `CliProcess.wouldReloadFor(spawnContext)`:
  `return !this.inFlight && !!this.model && (this._resolveModel(spawnContext) !== this.model
   || this._resolveEffort(spawnContext) !== this.effort);`
- `process-manager.getOrSpawn` reuse branch (229-246): before `return existing`, if
  `typeof existing.wouldReloadFor === 'function' && existing.wouldReloadFor(spawnContext)` →
  `await this.kill(sessionKey, 'model-reload')` (deletes from `procs`, preserves `session_id`) and
  **fall through** to the cold-spawn path → new proc spawns `--resume <session_id> --model <new>` →
  same conversation, new model/effort. Else `return existing` (unchanged).
- SDK procs have no `wouldReloadFor` → optional-call is `undefined` → reuse unchanged (SDK applies
  model live via `setModel`). In-flight cli procs → `wouldReloadFor` returns false → fold continues;
  the drift reloads on the next idle dispatch.
- Emit `cli-model-reload` event `{ sessionKey, from_model, to_model, from_effort, to_effort }` for
  forensics (so the prod watcher can confirm switches landed).

### Part 2 — Honest, backend-aware `/model` + `/effort` message

Replace the dead `=== 'channels'` check (slash-commands.js:209-212, 239-242) with a real
capability branch. For the cli backend:
- live proc + idle  → `Model → opus (claude-opus-4-7) — your next message runs as opus (conversation kept).`
- live proc + in-flight → `Model → opus (claude-opus-4-7) — applies after this turn (conversation kept).`
- no live proc → `Model → opus (claude-opus-4-7) — applies on your next message.`

SDK keeps its existing live-apply behavior (`anyActive ? "I'll switch when I finish" : ""`).
Determine cli via `pm.getBackend(sessionKey) === 'cli'`, with a no-live-proc fallback on the bot's
configured backend so the message is right even cold (getBackend returns null with no proc).

### Part 3 — `/config` card shows the running model

`formatConfigInfoText` (config-ui.js:67) already closes over `pm`. When a live proc exposes
`.model`/`.effort` (cli) and it differs from the configured value:
- `Model: sonnet (running) → opus (pending — applies on your next message)`
- `Effort: high (running) → max (pending — …)` (same when effort drifts)
Matched value, or no live proc → render as today (`Model: <configured> (<ver>)`).

## What this deliberately does NOT do

- No mid-turn model swap (the CLI can't; reload-on-next-dispatch is the contract).
- No change to SDK behavior.
- No new turn-lifecycle primitives — explicitly avoids the #15 seam; reuses `kill` + `--resume`.
- Does not touch `resetSession` / session-identity drift (model is NOT a `SPAWN_IDENTITY_FIELD`;
  reload preserves `session_id` and conversation — a reset would discard it).

## Tests (TDD red→green)

Unit:
- `CliProcess.wouldReloadFor`: model drift → true; effort drift → true; in-flight → false; matched →
  false; `this.model` unset → false.
- `process-manager.getOrSpawn` reload-on-drift: warm **idle** cli proc, drifted model →
  `kill` called + a NEW proc started (RED against current: returns existing, no kill). In-flight →
  reuse, no kill. SDK proc (no `wouldReloadFor`) → reuse. Matched model → reuse.
- `slash-commands` `/model` on cli: idle vs in-flight message text; SDK unchanged; effort parity.
- `config-ui` card: drift → `running → pending` line; matched / no-proc → plain line.

Real-claude E2E (the load-bearing bet): shumorobot Music topic — `/model opus`, send a message →
(a) the turn's transcript `message.model` = `claude-opus-4-7` (switch landed) AND (b) claude
recalls the prior discussion (conversation preserved). Both must hold.

## Risks

| risk | mitigation |
|---|---|
| Reload kills a proc doing background work (no in-flight turn but `_bgWorkSince` set) | `wouldReloadFor` could also gate on `!hasActiveBackgroundWork()`; v1 gates on `!inFlight` only — note as a follow-up; bg-work-during-config-change is rare |
| `--resume` + new `--model` doesn't actually switch the resumed session | the E2E proves it; if it fails, fall back to honest-message-only (Part 2) and drop Parts 1/3 |
| Drift check races a concurrent spawn | reuse branch already awaits `_starting` before the drift check |
| Effort flag name mismatch on respawn | verify the spawn arg for effort survives `--resume` (same E2E) |
