# Claude Code 2.1.283 via an SDK-driven pin — plan

Status: revised after a four-lens spec review and a two-lens re-review of the
SDK-driven design; awaiting owner sync.
Date: 2026-09-26.

## Problem

Production runs exactly what Polygram pins: Orchestra 0.10.21, which
pins the Claude CLI at 2.1.220 and `@anthropic-ai/claude-agent-sdk` at 0.2.123.
The SDK bundles CLI 2.1.123, and that is what shumorobot's SDK-backed chats
run. Upstream `latest` is CLI 2.1.283 / SDK 0.3.283 (`stable` is 2.1.274).
We want to be on `latest` and make future "move to latest" bumps cheap.

The current pin mechanism has two separate version numbers and depends on
Claude's auto-updater. The CLI pin is vendored by copying from
`~/.local/share/claude/versions/<v>`. The updater keeps only about the 3 newest
versions there, so 2.1.283 falls out within about 3 days. Every rollback
therefore needs a network `claude install` at boot.

## Decisions (owner)

1. `--model opus` moves to Opus 5.5.
2. Codex is out of scope. Its pin stays at 0.145.0.
3. The SDK path stays without `POLYGRAM_CLAUDE_BIN`.
4. **The SDK version sets the CLI version.** One exact SDK pin, and the CLI
   pin is that SDK's bundled `claudeCodeVersion`.
5. We pin to `latest`, not the `stable` dist-tag.

## Design: SDK-driven pin

SDK `0.3.N` ships its CLI as per-platform optional packages
(`@anthropic-ai/claude-agent-sdk-<platform>-<arch>[-musl]/claude`), and its
`package.json` records `claudeCodeVersion: "2.1.N"`. We verified that the
darwin-arm64 binary in `claude-agent-sdk-darwin-arm64@0.3.283` is
byte-identical to the auto-updater's `versions/2.1.283`: same SHA-256
`d8cb1e5c…1d21e` and the same Anthropic code signature (team `Q6L2SF6YDW`).
The VPS already installs `claude-agent-sdk-linux-x64` (glibc) with Polygram.

### Orchestra

1. **The version comes from the SDK.** `optionalDependencies`:
   `@anthropic-ai/claude-agent-sdk` `0.2.123` → `0.3.283` (exact).
   `CLAUDE_CLI_PINNED_VERSION` stays a literal (`'2.1.283'`), because Water
   installs with `--omit=optional` and has no SDK to derive from.
   - A unit test asserts that the literal equals the installed SDK's
     `claudeCodeVersion`. Bumping the SDK without the constant fails CI.
   - The SDK's `exports` map hides `package.json`. Read it from disk next to
     `require.resolve('@anthropic-ai/claude-agent-sdk')`.
2. **The vendor source comes from the SDK.** `ensureVendoredClaudeBin`
   gains a first obtain-step, before the existing copy from `versions/` and
   before `claude install`:
   - Resolve the platform binary the way the SDK itself does (`RG()` in
     `sdk.mjs`):
     - darwin: `-<platform>-<arch>`;
     - linux: glibc first, `-musl` first only on a host without glibc.
   - Resolve the platform package with `createRequire(<SDK dir>)`, the SDK's
     own context, not Orchestra's. If npm ever nests a second SDK copy, we
     still get the matching platform package.
   - A missing SDK (`MODULE_NOT_FOUND`, as in Water) falls through silently.
   - Use it only if the SDK's `claudeCodeVersion` equals the requested
     version and the platform package's `version` equals the SDK's
     `version`. Otherwise fall through to the existing steps unchanged.
   - **Validate before caching.** `npm i -g` extracts in place, and the VPS
     units restart after 5s, so a boot mid-install could copy a truncated
     binary that the fast path would then trust forever. After copying to the
     tmp file and before the rename, require that the size equals the source
     and that `<tmp> --version` prints the requested version. Apply this
     check to every source, not just the SDK one.
   - Log which source was used.
   - Keep the vendored copy and the fast path. Spawning straight from
     `node_modules` was rejected, because `npm i -g` replaces that directory
     under a running daemon.
   - Existing GC behaviour is unchanged: keep only the current version.
3. **Freeze-proof system prompt.** Add `--system-prompt-snapshot off` to the
   `CliProcess` spawn args, **only when the binary supports it**.
   - Why: since 2.1.267, a conversation records its `--append-system-prompt`
     once and reuses it on every resume until compaction. The recording is
     rolling out through server-side flags, so it may or may not be active
     for our account today. Polygram rebuilds that prompt on every spawn
     (display rules, richText, reply contract), so once it is active,
     toggling `/richtext` or shipping new prompt rules would silently not
     reach resumed chats.
   - **Detecting support.** 2.1.220 rejects the flag
     (`unknown option '--system-prompt-snapshot'`). At boot, run
     `<bin> --help` once and add the flag only if it lists
     `--system-prompt-snapshot`. This covers the gate's old side,
     `ORCHESTRA_CLAUDE_BIN` overrides to older binaries, and rollback.
   - **Argument placement.** Put the flag directly after
     `--append-system-prompt`, before the variadic `--settings` /
     `--mcp-config` / `--add-dir`. Pin the argv order in a unit test.
   - **Cost.** When the prompt text is unchanged, the bytes are identical
     and the cache still hits. When it changes (a `/richtext` toggle, a
     release with new rules), that request misses the cache and earlier
     extended thinking is dropped. That is the intended trade: we want the
     change to apply.
   - **Out of scope:** tool definitions stay recorded even with snapshot
     off. A changed reply-tool schema would not reach resumed sessions, so a
     release that changes the reply-tool schema must note that affected
     chats need `/new`.
4. `docs/CLAUDE_CODE_2_1_283.md` compat record, following
   `CLAUDE_CODE_2_1_220.md`: the triage below plus the probe results.
5. Update `tests/claude-bin.test.js` for the pin and the new source.
   Footer or dialog regex changes are made only if the live capture (probes)
   shows drift.
6. Release as **0.11.0** (minor, as for the 0.5 → 0.6 pin bump).

### Polygram

1. Dependencies:
   - `@shumkov/orchestra` `0.11.0`.
   - `@anthropic-ai/claude-agent-sdk` `0.3.283`.
   - Polygram keeps its direct SDK dependency, because the gate spikes in
     `scripts/spikes/*.mjs` import `query` from it. A unit test asserts it
     equals Orchestra's `optionalDependencies` pin, so npm dedupes to one
     ~240 MB copy.
   - `@anthropic-ai/sdk` moved from dependency to peer (`>=0.93`) in SDK
     0.3.x. Add it as an exact dependency (latest at implementation time) in
     **Orchestra**, which is the SDK's consumer at runtime. Nothing imports
     it directly.
   - `@modelcontextprotocol/sdk` 1.29.0 already satisfies `^1.29`.
2. `lib/sdk/build-options.js`: turn off the snapshot for SDK chats.
   - There is no top-level public option. The public form is
     `systemPrompt: { type: 'preset' | 'custom', …, snapshot: false }`
     (`sdk.d.ts` ~2356-2410).
   - `appendDisplayHint` currently returns a string or `string[]`. Wrap the
     final value as `{ type: 'custom', prompt, snapshot: false }`, or
     preset + append when the agent uses the preset.
   - Unit test on the composed options.
   - Production SDK chats always run the SDK's bundled binary, which matches
     its version, so the flag is always supported there. The gate spikes
     call `query` directly, not through `build-options`, so old-side SDK
     cells pointed at 2.1.220 never receive it.
3. `lib/model-costs.js`:
   - Add `claude-opus-5-5 { input: 4, output: 20, cacheRead: 0.20,
     cacheCreation: 5 }`. Prices are from the 2.1.280 changelog; cache
     creation is 1.25× input, like every other entry.
   - Fix the header comment: cache read is not always about 10% of input.
   - Move the "what `--model opus` resolves to" comment to the new entry.
   - Keep `claude-opus-5` for existing sessions.
   - Test: Opus 5.5 usage is priced at 5.5 rates, not the Sonnet fallback.
4. `lib/handlers/config-ui.js:223`: `opus: 'claude-opus-5-5'`, and update
   its test (`tests/handlers-config-ui.test.js:616`).
5. **Gate matrix re-baseline.** Rename `claude-2.1.220-matrix.json` →
   `claude-2.1.283-matrix.json` (`old: 2.1.220`, `candidate: 2.1.283`); git
   history is the audit trail.
   - **Per-version expectations.** `isCandidate` currently selects a set of
     expected behaviours, not just "which binary":
     - delayed MCP runs foreground on old, background on candidate
       (`claude-gate-matrix.mjs:171`);
     - subagent runs expect `taskUpdated === 0` on old
       (`subagent-gate.mjs:574-575, 638`);
     - `candidateOnlyInsertions` (`claude-gate-matrix.mjs:589-603`).

     With 2.1.220 moving to the "old" side, those expectations must become
     per-version values in the manifest. A 2.1.220 run must be checked
     against 2.1.220 behaviour, not 2.1.173 behaviour. This is the one real
     refactor in the plan.
     - Shape: `expectations: { "<cliVersion>": { delayedMcpMode,
       subagentTaskUpdated, taskReminderInsertions, resolvedOpus,
       workflowSizeGuideline, … } }`.
     - Replace every `isCandidate` (including `claude-gate-matrix.mjs:1463`)
       with `expectationsFor(run.attestation.version)`.
     - Fail closed when the attested version has no entry.
     - `candidateOnlyInsertions[].count` becomes a per-version
       `expectedCount`.
     - Copy the 2.1.220 values from the accepted 2.1.220 baseline evidence,
       not from memory.
     - Expectations are keyed by CLI version; the SDK version is held
       constant.
   - **Opus projection.** It expects `claude-opus-5-5`:
     - add the model to `RESOLVED_GATE_MODELS` (`claude-gate-evidence.mjs:47-50`);
     - update `:1016`, `opus-default-projection.mjs:40`.
   - **Workflow size-guideline projection.** Re-derive it: 0 of the 3 byte
     anchors match in 2.1.283 (`workflow-fixture.mjs:516-520`). The default
     is now plan-dependent ("medium", or "small" on Pro), and
     `claude-gate-evidence.mjs:1017` hardcodes `'medium'`.
   - **Replace remaining hardcoded version strings:**
     - `run-claude-gate-matrix.mjs:26`, `claude-gate-matrix.mjs:1463`,
       `subagent-task.mjs:114`;
     - `tests/claude-gate-matrix.test.js:12,479`, `tests/model-costs.test.js:65`,
       `tests/e2e-opus-5-real-claude.test.js`;
     - `tests/claude-executable-spike.test.js`, `tests/subagent-gate.test.js`,
       `tests/delayed-mcp-gate.test.js`, `tests/claude-workflow-fixture.test.js`;
     - `scripts/spikes/README.md` (8 refs).
   - **New matrix cell — system-prompt snapshot** (candidate only, through
     `CliProcess`). Guards our own contract across future bumps.
     - Control: snapshot on. Spawn with hint A, resume with hint B, and
       record which hint the model sees.
     - Test: the same run with snapshot off must see B.
     - If the control also sees B, recording is not enabled for this
       account. The cell then reports `NOT-APPLICABLE` with that evidence
       instead of `PASS`, so it cannot pass trivially.
   - **SDK cells:** both sides run SDK 0.3.283. The old side points
     `pathToClaudeCodeExecutable` at 2.1.220. We state that the SDK version is
     held constant rather than varied.
6. **One-off probes, not matrix cells.** Each probe is recorded in the
   Orchestra compat doc with its pass criterion.
   - **Dangerous `rm` in a bypass chat, triggered at least 4 times in one
     session.** Record the observed timeout (remote config tunes it:
     `timeoutMs:120000`, `maxDialogTimeouts:3`) and what happens after the
     3rd timeout.
     - **Pass:** every trigger ends in a deny within 5 minutes, and the turn
       completes with a reply through the bridge.
     - **If a `perm_req` / Telegram approval card also appears:** file a
       follow-up to suppress it. This does not block the release.
   - **Footer capture** while streaming, with one background shell, and with
     a queued (grey) message.
     - **Pass:** `STREAMING_HINT_RE` (`:178`) matches while streaming, and
       `BACKGROUND_SHELL_RE` (`:195`) extracts count 1.
     - **Fail:** fix the regex in this release.
   - **Trust dialog and session-age dialog** on 2.1.283.
     - **Pass:** both are auto-handled with no `session-age-dialog-fallback`
       event.
     - Skip this probe if the existing `cli-contract` cell already exercises
       them; say so in the compat doc.
   - **Rollback direction:** 2.1.220 (no snapshot flag) resuming a
     transcript written by 2.1.283.
     - **Pass:** a reply is produced.
     - **Fail:** the rollback runbook says affected chats need `/new`. This
       does not block the release.
7. `AGENTS.md`: rewrite only the pin-procedure section for the new mechanism
   (see "Moving to latest"). Stale statements elsewhere, such as about banner
   art, are flagged, not edited.
8. Release as **0.39.0** (minor: default model and SDK tool-set behaviour
   change).

### Moving to latest (future bumps)

1. Open a tracking issue.
2. In Orchestra, run `npm i @anthropic-ai/claude-agent-sdk@latest --save-exact`
   and set `CLAUDE_CLI_PINNED_VERSION` to its `claudeCodeVersion`. The CI test
   enforces the match.
3. Triage the CLI changelog from the old pin to the new one.
4. Run the gate matrix with the old vendored binary and the new SDK platform
   binary.
5. Release Orchestra, then Polygram.

## Rollout

1. Gate: full authoritative `PASS` of the 2.1.283 matrix, plus a pass verdict
   on every probe. Binaries are archived at
   `~/.local/share/claude-pin-archive/` with `SHA256SUMS`.
2. Orchestra PR → 0.11.0. Then the Polygram PR → 0.39.0. Every release
   commit records old → new version and the triage summary.
3. **Rollback prep before any host boots 0.39.0.**
   - **VPS:** copy `~/.local/share/polygram/claude-bin/2.1.220` to
     `~/.local/share/claude-rollback/2.1.220` and record its SHA-256. Boot GC
     deletes every non-pinned vendored version, and `versions/` no longer
     holds 2.1.220.
   - **Mac:** the archive already holds 2.1.220. shumorobot currently runs
     `runtime/current → releases/0.38.6`; keep that release directory.
4. **shumorobot** (Mac, SDK backend): deploy. This moves its chats from
   bundled 2.1.123 to 2.1.283. Soak 24h.
5. **VPS CLI backend: restart both bots together.**
   - A staged per-bot soak is not possible. Both units run the same
     `/usr/lib/node_modules/polygram` install as user shumabit and share
     `~/.local/share/polygram/claude-bin`. The first 0.39.0 boot deletes
     `2.1.220` through GC, which would kill every new CLI spawn in the other
     bot while it still runs old code.
   - The 24h soak after this step is the CLI soak; shumorobot does not
     exercise the CLI backend.
   - Use the standard polygram-deploy flow (in-flight gate, release gate,
     `better-sqlite3` guard, no `--omit=optional`).
   - The boot log must read
     `CliProcess pinned to claude CLI v2.1.283 … (vendored)` with the SDK
     source and no WARNING.
6. **Soak signals.** Events DB, per host, 24h after the deploy compared with
   the 24h before it. **Rollback triggers** (any one):
   - `session-age-dialog-fallback` > 0;
   - any "tmux session disappeared after ~15ms";
   - `startup-auto-retry` > 10/24h (baseline 4–5);
   - `autosteer-match-miss`, `autonomous-wakeup-message`,
     `tool-only-completion` or handler errors more than 2× baseline, with
     at least 5 events;
   - any Opus-session cost row priced at Sonnet rates.

   Anything else new (for example SDK chats hitting missing Grep/Glob) gets a
   ticket, not a rollback.
7. **Rollback.** Reinstall the previous Polygram version.
   - VPS: first copy `claude-rollback/2.1.220` atomically back into
     `polygram/claude-bin/`.
   - Mac: repoint `current` to `releases/0.38.6`.
   - Chats whose transcripts 2.1.220 cannot resume need `/new`, per the
     probe.

## Failure modes

| Failure | Detection | Response |
|---|---|---|
| SDK platform package missing (`--omit=optional`, unsupported platform) | boot log shows the `versions/` or `claude install` source | Existing fallback steps; Water relies on this |
| Platform package version ≠ SDK version | source-selection check | Skip it and fall through; logged |
| Footer drift breaks busy/background detection | footer probe; `autosteer-match-miss` | Orchestra patch with a regex fix |
| Resume semantics lose continuation after restart | clean-restart-resume spike; soak | Fix or roll back |
| Prompt snapshot re-enabled or ignored | matrix cell | Block the bump |
| Truncated binary vendored during `npm i -g` | size and `--version` check before rename | Skip the source; the next boot retries |
| Old binary receives `--system-prompt-snapshot` | `--help` feature detection | Flag omitted |
| SDK chats on the VPS spawn from `node_modules` during `npm i -g` | — | Existing risk, unchanged by this plan (the SDK path is unpinned by decision) |
| Dangerous-`rm` approval card answered after auto-deny | probe | Suppress the card for that case (follow-up) |
| Rollback finds no 2.1.220 | pre-deploy copy | Copy-back step |
| Water and Polygram run different CLIs on a shared `~/.claude.json` (VPS) | soak: auth and trust regressions in either app | Water bumps Orchestra separately |

## Out of scope

- Codex.
- Water's Orchestra bump.
- A canary that auto-tracks newer-than-pinned versions. shumorobot follows the
  same SDK pin.
- Events retention and other unrelated cleanups.
