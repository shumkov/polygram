# 0.12.0 — Stable-release plan

> Authored 2026-06-12 from rc.40. Goal: get from `0.12.0-rc.40` to a confident
> `0.12.0` stable. No code blockers exist today — this is a polish + soak +
> doc-honesty plan, not a bug hunt.

## Definition of "stable" (exit criteria)

Tag `0.12.0` only when ALL hold:
1. Suite green (currently 2510/0), boot-smoke + the new cancel/config E2Es pass.
2. rc.41 (this plan's fixes) has soaked ≥24h fleet-wide with the cancel + config
   paths exercised in real use, and:
   - zero `uncaught-exception`, zero `cli-multi-pending-assert`,
   - zero `TURN_TIMEOUT` that discarded a delivered reply,
   - zero `session-age-dialog-fallback`, zero `cli-delivery-watchdog-escalate`,
   - `cancel_mode:interrupt` dominates `abort-requested` (kill only for real bg/ghost),
   - `startup-auto-retry` stays at its ~contained baseline AND every one auto-recovered.
3. Every recurring prod event is fixed, humanized, or explicitly accepted as
   upstream-with-a-filed-report. No user-facing surface leaks raw internals.
4. `TODO.md` + `docs/0.12.0-known-issues.md` are honest (no stale/misleading entries).

## What is NOT a blocker (explicitly post-stable)

Deferred features (SessionStart cwd pairing, context/token observability,
hot-reload agents, approval-waiting stub), the format-aware chunker, the
`assembleHandlers()` refactor, full README rewrite, the verbatim-re-delivery
issue (#3 — upstream, documented, every fix rejected).

## Phase 1 — Quiet the known noise (the "shumabit health" alerts)

The screenshotted alerts are the visible face of the resume race; they read as
errors but are auto-recovered transients or already-fixed conditions.

- **1a. Humanize CLI-backend error messages** (known-issues #2). Map the
  CLI/channels failure kinds (`TMUX_SESSION_GONE`, startup-gate timeouts, the
  absolute/idle turn-timeout ceilings) in `lib/error/classify.js` to friendly
  copy with an action hint, like the SDK kinds already have. No user should see
  `tmux session disappeared … ▰▰▰ 27%`. TDD red→green. **~1–2h.**
- **1b. Tune the health monitor** (the `shumabit health` job, lives under the
  shumabit user). An auto-recovered `startup-auto-retry` should NOT page as an
  error; alert only on (i) a death with no recovery within N seconds, (ii) a
  repeat above the ~1/day baseline, or (iii) a genuinely terminal kind
  (uncaught-exception, multi-pending-assert). This stops the noise at the
  source. **~1h** (it's a log/events query tweak, not polygram code).
- **1c. Confirm the rc.38 idle-timeout fix held** — no `reason=idle`
  turn-timeout since the consumed-ack deploy (verified: last was 06-11 19:49,
  pre-rc.38). Pin it as a soak watch, no code.
