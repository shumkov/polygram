## Commit sequence (logical, each independently revertable)

Per the "commit per logical change" preference. Each commit must keep
the test suite green.

### Commit 1 — Drop `requestRespawn` plumbing

`requestRespawn` was a CLI-pm-only mechanism for `/effort` and `/model`
mid-session config changes that the CLI pm couldn't apply without
respawning the subprocess. SDK pm uses `applyFlagSettings()` instead.
Call sites in polygram.js call `requestRespawn` with a `typeof === 'function'`
guard, so on SDK pm they're already no-ops.

- Delete the call sites in polygram.js (lines around 1964-1967, 2336-2338).
- Drop the `requestRespawn` field from `lib/pm-interface.js`.
- Drop the `requestRespawn` forwarder from `lib/pm-router.js`.
- Drop the optional-method comment from `lib/process-manager-sdk.js`.
- Tests: existing `process-manager.test.js` exercises CLI pm's
  `requestRespawn`. We're keeping CLI pm in this commit; those tests
  stay. They go in commit 6.

### Commit 2 — Drop `pm.isSdkFor(sessionKey)` conditionals

Every call returns `true` post-cleanup (only SDK pm exists). Inline
the branch.

- polygram.js: 5 call sites (lines 2158, 2185, 2770, 2834, 2980).
  - `if (!pm.isSdkFor(sessionKey)) { ... else-only-branch ... }` →
    keep only the SDK-pm branch.
  - `pm.isSdkFor(sessionKey) && X` → just `X`.
- Tests: any test that mocks `isSdkFor` to return `false` is exercising
  the CLI-pm path → flag for deletion in commit 6.

### Commit 3 — Inline `pm.pickFor(sessionKey)`

Every call returns the same pm (single-pm world). Replace
`pm.pickFor(sessionKey)` with `pm` directly.

- polygram.js: 6 call sites (1964, 2289, 2336, 2920, 3481, plus the
  one that's already covered by commit 1).
- Drop `pickFor` from `lib/pm-interface.js`.
- Drop `pickFor` from `lib/pm-router.js` (or collapse the entire router).

### Commit 4 — Collapse pm-router to single-pm wrapper

With pickFor / isSdkFor / requestRespawn gone, the router becomes a
thin pass-through that just instantiates SDK pm and exposes its
methods. ~150 lines deleted.

- `lib/pm-router.js`: rewrite as single-pm wrapper, ~50 lines.
- Drop the `useSdkAll` / `sdkChats` opts.
- Future: when an alternate pm impl arrives (pi-agent-core adapter,
  test pm), the router gains the multi-pm branching back. The
  interface JSDoc in `pm-interface.js` is still the canonical contract.

### Commit 5 — Drop `POLYGRAM_USE_SDK` / `POLYGRAM_SDK_CHATS` env vars

- polygram.js: drop `const USE_SDK = process.env.POLYGRAM_USE_SDK === '1';`
  and the `sdkChats` parsing.
- Drop the boot-time logging that reports the chosen pm.
- `start-sessions.sh` on shumabit: drop the `POLYGRAM_USE_SDK=1` prefix
  on both bot launches (cosmetic — env var would just be ignored).

### Commit 6 — Delete `lib/process-manager.js` + 3 test files

The actual file deletion. Test count drops by 1201 lines (~80 tests).

### Commit 7 — Delete `bin/approval-hook.js`

CLI pm's canUseTool IPC bridge. SDK pm wires canUseTool in-process so

- Drop the bin/ entry from `package.json` if present.
- Drop `bin/approval-hook.js`.
- Audit `scripts/ipc-smoke.js` for `approval_request` IPC handler;
  remove if dead.

  2. All 1438+ tests green at every commit (no test-then-fix-later).

  same release.yml path. `latest` flips automatically (no -rc suffix).

- The router file extension preserved as a forward-compatible seam,
  per §7.0.5 closing paragraph: *"Why router stays even after CLI pm
  is gone: future alternate pm impls can slot in cleanly behind the
  same interface."*
