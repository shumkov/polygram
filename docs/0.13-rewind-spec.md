# 0.13 — Telegram `/rewind` (conversation rewind) — spec

**Status:** design for review (not implemented). Gated on a P0 spike (below) that
proves the core mechanism on the pinned CLI before any feature code.
**Origin:** operator idea (2026-06-09) — "reply to my message with `/rewind`; you run
it when the turn ends; use esc-esc, or any claude-CLI option if one exists."

---

## ⚠️ Scope boundary — read this first

`/rewind` reverts the **conversation** — claude's memory of the turns, and the visible
chat. It does **NOT undo real-world side-effects** claude already performed: files
created in Google Drive, a published Sheet, emails sent, external API calls. Those
persist. claude's own checkpoints track **file edits only** (snapshots before its edit
tools), not bash side-effects and not external systems (confirmed in the CLI docs).

So `/rewind` means **"take back what was said and re-decide from here,"** not **"undo
what the bot did in the world."** (The hiring incident's Drive folder + Sheet would
still exist after a rewind — claude would just forget it made them.) Undoing actions is
a *separate* feature and out of scope here; if both are wanted, `/rewind` can end by
asking claude "you've been rewound to before X — do you want to reverse anything you did?"

## UX

- The operator **replies to one of their own past messages `M`** with the text `/rewind`.
- `M` is the rewind target: the conversation is restored to **just before `M`** — claude
  forgets `M` and everything after; the chat is trimmed to match.
- Executes **after the current turn ends** (you can't rewind a live turn — the transcript
  is mid-write and the agent is busy). polygram queues it and fires on turn-resolved.
- Confirmation back to the chat: "⏪ Rewound to: «first line of M». N messages removed."

## What the claude CLI actually offers (investigation, 2026-06-09)

- **Esc-Esc / `/rewind`** opens an interactive rewind menu — **TUI-only**. There is **no
  programmatic/headless API** and **no way to target a checkpoint by id**; the menu is
  positional (arrows + Enter). Actions: restore code+conversation / conversation / code,
  or summarize.
- **Checkpoints** = per-prompt snapshots of **file edits only** (not bash effects, not
  external systems). Persist across resumes; 30-day cleanup.
- **`--fork-session`** (with `--resume`/`--continue`) creates a **new session id** from a
  resume point — a documented flag.

## Approaches

### A — drive the native rewind UI (Esc-Esc), capture-pane-verified — **recommended**
claude runs in a tmux pane (TUI) on the channels backend. polygram: ensures the prompt is
empty (`Esc`), opens the menu (`Esc Esc`), **reads it via capture-pane**, navigates to the
target row, picks "Restore conversation", confirms — **verifying each keystroke against a
fresh capture** (closed loop, not blind spraying). claude's own tested rewind does the
actual state mutation; polygram only navigates.

**Targeting is reliable** (this was the operator's correction): the operator replied to `M`,
so polygram already has M's exact **text + timestamp + msg_id**, and the rewind menu **shows
each checkpoint's prompt text** — polygram matches M to the row by text (order/timestamp to
disambiguate repeats). Determinism comes from *reading* the menu, not from editing a file.
The real residual risk is NOT "hit the right point" but: (a) **granularity** — the menu lists
claude PROMPTS, and autosteer can fold several TG messages into one prompt, so the finest
rewind boundary is the claude-prompt, not always the individual message; (b) **TUI timing/
state** — the menu must render and the prompt must be empty. Both are bounded and P0-validated.
Channels/cli backend only (needs the TUI).

### B — transcript fork + resume (polygram-side) — **rejected (failure blast radius)**
polygram cuts claude's session transcript JSONL at the entry wrapping `<channel msg_id="M">`,
writes the prefix to a forked session id (`--fork-session`), and respawns with `--resume`.
Deterministic and no TUI navigation — **but polygram does the dangerous state mutation itself,
on claude's *undocumented* transcript format.** A bad cut (dangling `tool_use`, a missed
compaction/summary marker, or a CLI-version format change) can make the session
**unresumable — losing the whole conversation, silently.** Rejected: its failure mode is
*corruption*, vs A's benign *wrong-target/no-op*. Don't reverse-engineer and rewrite a tool's
private persistence when its supported (if awkward) interface exists.

### C — ask claude to "rewind itself" — rejected
claude can't remove its own prior turns from its context; telling it to "pretend we're
back at M" leaves the context intact. Not a real rewind.

## Recommendation

**A — drive claude's native rewind, capture-pane-verified.** Revised 2026-06-09 after the
operator challenged the earlier "B is safer" call (twice — correctly). The deciding metric
is **failure blast radius, not determinism**: B's failure is *corruption* (editing an
undocumented session file → possible total conversation loss, silently, on any format
change); A's failure is a *benign wrong-target/no-op* because claude's tested rewind does
the mutation and polygram only navigates. Targeting is reliable in A too (polygram knows M
+ reads the menu). Principle: use the supported interface before rewriting private persistence.

## Design (Approach A)

| Step | Detail |
|---|---|
| Trigger | inbound message, reply-to `M`, text `/rewind` (admin-gated — only the paired operator). Distinct from the `ask` free-text path. |
| Defer | enqueue `{sessionKey, targetMsgId}`; execute on the next `stop-hook`/turn-resolved for that session (claude idle, prompt empty). Never mid-turn. |
| Open menu | send `Esc` (clear any prompt text), then `Esc Esc`; capture-pane to confirm the rewind menu rendered. |
| Locate row | match M's text (the operator's reply target, known exactly) against the menu's listed prompts; compute the up/down distance to that row. (Account for autosteer-folded prompts.) |
| Navigate + select | send arrow keys; **capture-pane to verify the highlight is on M's row** before `Enter`; choose "Restore conversation"; confirm. Abort safely ("Never mind") if the capture doesn't match. |
| Respawn | none needed — claude rewinds in place. |
| TG cleanup (DEFAULT) | delete the bot's messages after `M` **by default** (operator decision 2026-06-09) so the chat matches the rewound state. The bot can always delete its own; the operator's own messages only if the bot is a group admin (else they remain). |

## Hard parts / risks (Approach A)

- **Menu state / timing** — Esc-Esc only opens the menu when the prompt is empty and claude
  is idle; the menu must finish rendering before reading. Mitigate: deferral to turn-end +
  capture-pane gating each step + a bounded retry, and **fail safe** (abort via "Never mind",
  alert the operator) if a capture doesn't match the expected shape.
- **Prompt granularity** — the menu lists claude PROMPTS; autosteer can fold several TG
  messages into one prompt, so the finest rewind boundary is that prompt. If `M` was batched
  with later messages, the rewind lands at the batch boundary (document it; confirm the
  landing point back to the operator).
- **Row matching** — match the menu row by M's prompt text; identical repeated texts need
  order/recency to disambiguate. (Claude's menu shows the prompt text, which makes this far
  more robust than blind counting.)
- **TG deletion asymmetry** — the bot deletes its own messages freely; the operator's only
  if the bot is a group admin. Document that user messages may remain visible.
- **Backend scope** — cli/channels only (needs the TUI). SDK backend out of scope.
- **Concurrency** — a `/rewind` racing a newly-arriving turn; the deferral + a per-session
  lock handle it.

## Phased plan

- **P0 — spike (gates the feature).** On the pinned CLI (2.1.158), in the **bridge-driven
  channels TUI**: confirm `Esc Esc` opens the rewind menu, that capture-pane reliably reads
  the menu (rows = prompt texts), and that arrow-navigate + "Restore conversation" actually
  rewinds the conversation. **No feature code before P0.** (If the menu can't be driven
  this way, fall back to B with all its corruption caveats, or shelve.)
- **P1** — `/rewind` detection + admin gate + turn-end deferral + the confirmation message.
- **P2** — the capture-pane menu drive: open → read → match M's row → verify → select.
- **P3** — Telegram message cleanup (bot's own by default; operator's if admin).
- **P4** — UX polish: preview of the target + landing point, "N messages removed", and the
  optional "want me to reverse anything I did?" prompt for side-effects.

## Open questions

1. **Restore "conversation" vs "code + conversation"?** For channels chats claude rarely
   edits local files (it acts on Drive/external), so "Restore conversation" is the default;
   "code + conversation" only matters if the agent has a local working tree it edited.
2. **Trigger surface** — `/rewind` reply only, or also a reaction (e.g. ⏪) on a message?
   `/rewind` reply is unambiguous; esc-esc is the internal *mechanism* (driving claude's
   menu), never the user-facing trigger.
3. **Side-effect reversal** — keep strictly out, or add the end-of-rewind "reverse actions?"
   prompt (P4)?
4. **Scope of cleanup** — ✅ RESOLVED (operator 2026-06-09): delete the bot's messages
   after M **by default** (no `--clean` flag). Operator's own messages deleted too when the
   bot is admin; otherwise they remain (Telegram limitation).
